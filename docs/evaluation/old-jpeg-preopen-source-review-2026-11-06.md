# Managed old-JPEG preopen deferral: source-only review

This review concerns separately versioned candidate20 only; no build, decoder or OJPEG fixture was executed. It is not a production adoption approval.

The guard is placed before all three managed `Tiff.ClientOpen` calls used by full fallback Decode, Band and snapshot validation. Classification reuses the bounded first-IFD parser and adds flags to its internal header. It does not follow JPEG streams, later directories or SubIFDs. Metadata-only admission/dimensions remain separate from pixel refusal. Existing post-open-only deferral could not prevent OJPEG header work during directory/scanline initialization; moving this managed guard is therefore necessary for its stated scope.

The raw Compression6 rule and Compression7 plus nine legacy tag identifiers match the fork's `checkJpegIsOJpeg` source: its normalization tests raw directory tag presence, not successful typed field assignment. JPEG tables347 alone is correctly excluded. Integer storage is read at its actual width and low16 normalization mirrors the fork. Per-sample inspection is bounded and conflicting values are classified before managed open. The proposed new representation-policy refusals still need explicit parent approval and baseline inventory.

A concrete documentation discrepancy was reported and corrected before execution. The original wording implied that scalar zero/unknown codec values set the unqualified flag. The actual flag covers noninteger **storage**, zero/over64 **element count**, and conflicting per-sample values. Scalar0/unknown integer codec values retain existing downstream behavior unless their normalized value triggers the named old-JPEG rule. The source was not widened to create an unregistered global codec whitelist.

No high-confidence blocker was found in this narrow managed-only guard. Its public limitation is material: current ImageDecoder attempts Skia first. Thus this patch cannot establish universal pre-parser old-JPEG refusal across native backends/RIDs, and must not be reported as a complete OJPEG resource fix. Moving TIFF preflight before native parsing would introduce a separately reviewed admission policy, including existing metadata/segment caps for formerly native-admitted inputs. Metadata-only native parsing must also be considered if the intended promise is avoiding every old-JPEG header parser.

Before execution, retain valid-small OJPEG baseline inventory (currently absent), raw6 and each legacy-tag marker, standard JPEG7+tables347, II/MM/Classic/BigTIFF and storage/count forms. Header-only payloads can prove a policy refusal reason but cannot establish valid OJPEG capability. Verify controlled reasons survive each public managed fallback route, source bytes remain unchanged, and ordinary non-OJPEG output/first-frame behavior stays fixed. No oversized nested SOF or entropy experiment is authorized by this review.
