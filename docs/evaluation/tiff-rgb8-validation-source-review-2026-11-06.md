# RGB8 validation buffer proposal: independent source review

This is a read-only review of isolated candidate19, based on candidate16. No candidate19 build, decode, timing or output assessment has occurred. The proposal freeze is `366b29eb3cce6cd9704d006a7eafea27df4fc86c85220117e4a8e5d950aed97c`; production retains ImageSharp.

No high-confidence source blocker was found in the narrow validation-only dispatch. `TryValidateContiguousRgb8` requires unsigned8-bit RGB with three contiguous samples, no nonzero extra-sample count, and compression1/5/8/32946/32773. JPEG/OJPEG, alpha, gray/palette, planar and non-unsigned layouts remain on existing branches. This does not qualify the existing OJPEG path. The fork's per-sample field reader explicitly rejects differing sample values; the new branch does not authorize heterogeneous channels merely by inspecting the common field.

For tiled layouts, checked geometry must match `TileSize`, the existing decoded-block cap remains, and every spatial first-IFD tile is read into one reused exact-sized destination. A short decoded count throws. For strips, checked `ScanlineSize` must match RGB width; every row is read sequentially and any failed read throws. Existing first-IFD preflight still checks all segment extents/counts and budgets before decoder use. The enclosing diagnostic sink still rejects reported errors. The change does not bypass first-IFD validation or substitute a first successful block for later blocks.

The public mode **does not change**: `ImageValidation.cs` still returns `tiff-first-frame-decodability-blocks` for this TIFF path. There is no approved blocks-to-samples oracle relaxation. Conservative allocation flags remain based on a source tile covering the page or rows-per-strip covering its height. Reusing one row buffer does not bound the vendor's retained strip state, aggregate allocations, native scratch or total process RSS. Full/rendered decode, bounded decode and band dispatch are untouched and must retain exact pixel output.

Actual malformed-codec behavior remains an empirical gate. A decoder may report a recoverable stream as decodable; this review does not turn the contract into strict compressed-bitstream validity. Late compressed checksums, truncated final tiles/strips, predictors and malformed decoded byte counts need baseline-first comparisons. Candidate19 may neither silently accept a formerly rejected case nor drop a formerly admitted case without separate policy review.

A source-only independent generator is prepared at `.artifacts/experiments/sec01-independent-v1/rgb8-v19-review/generate.py`. It constructs16 unseen containers without an imaging library: eight valid RGB8 cases spanning all five allowed compression tags, strips/partial-edge tiles, II/MM, Classic/BigTIFF, predictors1/2 and orientation6; each has a corresponding final-block-only mutation. Deflate variants alter the final Adler32 byte without changing source length. Raw/LZW/PackBits variants halve the last declared encoded count while leaving offsets and source length intact. These distinguish metadata admission from final payload decompression decisions; they are not assumed to have a particular corruption refusal outcome before baseline observation.

The generator has not run during the coordinated quiet period. After release, input hashes and structure must be frozen before exact A16 assessment; all eight valid cases must first be accepted. Freeze actual A16 complete decisions/code/dimensions/mode/flags/source identity before inspecting candidate19. Retain the existing154 snapshot and17 variant controls, all eligible historical cases, ineligible controls, and unchanged rendered pixel matrices. Then seek a separate registered resource window. None of the prior archive-allocation/latency regressions is erased by this source proposal.
