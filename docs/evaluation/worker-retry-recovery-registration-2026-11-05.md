# Delayed input retry recovery control

Status: new proposal/source only, no worker dispatch. Root identified a missing acceptance axis before production adoption: the idle-only candidate skips the old wait after a non-null Pending retry and can exhaust a transient failure before its input becomes available. The completed primary400no-op/800generated/120page-visit campaign remains untouched; exact final attempt counts alone cannot establish recoverability.

Fresh stores contain exactly one recognition job, one project/surface/line, no sentinel and no L1/L2. The job targets a common owned package path that is initially absent. No optimizer is restored, no source/locked labels are opened and no training or scoring occurs. Root's original baseline109-file package and original null-only candidate remain unchanged.

Run baseline then candidate once, sequentially. Define readiness as the controller's first observation of the owned worker's polling banner; retain its raw/observed timing. At exactly target1.25seconds after readiness, create an atomic owned symlink to the immutable existing model package. This is a trusted local pkg-path control, not a public registry symlink permission change. Record actual publication offset; do not change the delay from partial results. At target2.75seconds, inspect the full raw jobs/native state, then signal the owned worker and allow at most10seconds to drain, followed by owned-group termination if required. Retain the final complete state, all logs/failure strings, source/model hashes and actual times. Remove only the exact symlink created by this run, after worker exit.

Expected counterexample, fixed before outputs: baseline retries about0/1seconds, then succeeds after the1.25second publication with one L0; null-only candidate exhausts four attempts before publication and remains Failed with no L0. If this does not occur, retain the outcome and investigate without adjusting timing or rerunning adaptively. This is a functional recovery counterexample, not a comparative throughput claim. If confirmed, root may propose a **new** isolated candidate that delays when the result is null **or Pending**, retaining the prior retry opportunity interval while draining successful work promptly.
