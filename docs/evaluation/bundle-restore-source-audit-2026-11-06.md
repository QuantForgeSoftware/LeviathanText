# Bundle, backup and restore source audit

Source-only review during the long API measurement quiet window. No backup, restore, ZIP/PDF export, build, test, HTTP, model or corpus operation ran. Original source/test anchors are recorded under `.artifacts/experiments/bundle-restore-source-audit-v1`; the PDF renderer and bundle changes have separate preserved originals and candidate freezes.

## High-confidence findings and current status

1. **PDF derivative overwrite.** Predictable page names were published with File.WriteAllBytes into explicitly reusable output directories. A same-stem import could overwrite an existing capture before the project save, including when a later optimistic conflict prevented the new object from being saved. Root approved a narrow non-overwriting fix: all-target preflight and exclusive CreateNew publication, with no deletion rollback. Source and generated regression/API cases are prepared, not executed. See `docs/tasks/pdf-derivative-publication-2026-11-06.md`.
2. **Ambiguous bundle derived output.** Capture GroupBy/First could embed the first same-ID image for multiple surfaces; duplicate surface IDs could create duplicate ZIP paths and first-match exports. Native project.json and original image files were not deleted. Root approved native rescue for these exact identity ambiguities; source and five generated regressions are prepared without execution. See `docs/tasks/bundle-native-rescue-2026-11-06.md`.
3. **Restore verifies SQLite integrity but not readable native payloads.** VerifyBackupDatabase currently performs quick_check, rejects newer user_version, and prepares projects columns with LIMIT0. A checksum-valid SQLite snapshot containing malformed/null/unsupported native JSON or row/native ID disagreement can therefore replace a healthy --force target before later LoadProject fails. Current-schema missing required columns/tables can likewise pass this minimum query. This is source-derived, not yet an executed regression. Root requested a bounded read-only verification contract before edits; it is not fixed by the preceding two changes.

The proposed restore boundary streams project rows, loads the current native envelope, checks non-null Collection identity against the row and consistent contract metadata, and validates current-schema required query shapes. Genuine older SQLite schemas must remain eligible without migration or rewriting during verification; existing zero-version startup repair and legacy duplicate inner identities must not be silently normalized or rejected as part of this check. A genuine old-v7 table without a version column is an explicit positive control. Comprehensive migration/schema/data semantics remain separate gates.

## Existing protections verified by source and existing test inspection

- Bundle publication stages into a sibling temporary file and replaces the destination only after archive completion. Existing source-capture destination and directory-link checks remain before publication. Hard-link aliases are not inherently overwritten in place by a staged rename; do not report them as a truncation bug without evidence.
- Opt-in bundle images use a bounded byte snapshot, actual image validation, a per-image25MiB and total250MiB copied-byte limit, and recorded SHA verification. Renamed raw text/truncated image controls already exist. This remains the ImageSharp path; no SEC prototype was adopted.
- Current ProjectBundle only creates ZIPs. No bundle ZIP extraction/import path was found. Model registry archives are a different subsystem; hypothetical ZipSlip must not be attributed to a nonexistent bundle importer.
- CLI backup refuses an existing target, stages SQLite VACUUM INTO plus copied images/checksums, and publishes the completed directory. Restore validates image basenames/duplicates, direct link/obstruction/sidecar conditions, checksum-verifies staging, publishes images before the DB, and rolls image changes back on ordinary publication errors. Existing tests cover traversal names, obstructed images, explicit destinations, replacement/unlisted-image behavior and non-SQLite payloads.
- Capture relocation hashes all selected candidates before one optimistic save, keeps capture/frame/rights metadata unchanged, checks canonical tree escape and overlapping roots, and records an attachment receipt. Existing tests cover source/destination links, identity mismatches, unreadable originals, dry-run and concurrent-save conflicts.

These are source/test-coverage observations, not rerun receipts. The operations guide explicitly requires stopped services for coordinated backup/recovery; filesystem/SQLite multi-file crash atomicity, externally changing image trees and instant authorization revocation are not guaranteed by the ordinary-error rollback.

## Remaining bounded risks and limits

Restore currently reads the full manifest and accepts an unbounded count/total of local backup image entries. Staging preserves the target on ordinary early failure but does not impose a disk/CPU quota. This is a CLI/local-input resource-policy gap, not a demonstrated remote upload vulnerability. Existing source/target metadata checks also do not establish race-free protection from hostile concurrent symlink/file replacement. Backups are integrity-checked, not authenticated signatures establishing a trustworthy backup creator.

A restored DB retains stored capture paths; copying adjacent image-cache bytes does not automatically rebind every absolute or external capture location. Existing relocation is explicit, and external capture files need their own backup as documented. Do not claim automatic portable rebinding from the SQLite restore workflow.

Ordinary project imports retain their existing request-admission authorization and optimistic DB save behavior. RequestProjectStore's commit-time BindAuthorized mechanism is used for the stricter NativeAI path, not automatically every import. Extending commit-time role/membership checks to other operations needs an explicit capability policy, particularly admin-only host-path imports and separate derivative-file publication. No broader authorization race was executed or corrected by this audit.
