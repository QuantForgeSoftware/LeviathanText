# Isolated automatic worker renewal: implementation and independent controls

This remains an isolated prototype, disabled by default and not integrated into main. It reuses existing LeaseInfo.ClaimId without schema/contract changes. The engine compiles with zero warnings/errors after a preserved compiler-only Task.Run return-inference correction. Main source parity and candidate binaries are frozen under `.artifacts/experiments/worker-heartbeat-engine-v1/`.

Independent tester B observed two actual original defects before candidate behavior: a synchronous blocked RunNext handler outlived its lease without manual heartbeat, and a nonce-less heartbeat renewed a same-worker replacement attempt. B separately owns the16-control lifecycle suite and a real two-process automatic-renewal proof. Those receipts must not be conflated with the durable-store controls here.

The17 candidate-only durable controls pass (`durable-v2.log` and TRX). They use actual private SQLite stores and independent peer connections: exact nonce renewal and monotonic timestamps; wrong/missing/stale worker/claim/job, legacy null nonce, cancelled/terminal/no-lease refusal with exact raw JSON preservation; same-worker replacement protection; and actual independent write contention returning Contended without mutation, followed by successful renewal after release. Two additional tests each execute eight fixed peer races against cancellation or replacement and verify no resurrection or overwrite of the new claim. These are useful concurrent outcomes, not a claim that every possible CAS interleaving was deterministically forced.

The renewal operation performs one read and at most one exact-JSON CAS, uses a zero-wait process-local write gate and bounded provider command waits. Provider timeouts are not hard native execution guarantees. Its peer belongs to the renewal task, which is stopped and joined before finalization. Fault summaries are bounded, and a renewal failure cannot manufacture a retry/receipt or authorize reclaim of a still-publishing expired handler. Existing nonce-less manual calls intentionally refuse; manual callers migrate to the captured-claim HeartbeatAttempt method. Old worker binaries can erase nonce fields and require a drain/version policy, not a claim of safe mixed-version operation.

Outstanding adoption gates include root source review, B's separately registered process/cleanup proof, existing worker semantics with the positive manual fixture migrated, full integration checks and a later resource/overhead registration if enabled. No throughput, exactly-once publication, universal shutdown bound or automatic recovery claim follows from these functional controls. No model, training, provider or corpus operation ran.
