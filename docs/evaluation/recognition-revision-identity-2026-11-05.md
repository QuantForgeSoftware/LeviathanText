# Recognition revision identity correction

The independent imaging/worker review identified a pre-existing data-integrity bug: `RecognitionPipeline` truncated each line suffix to 24 characters when creating an L0 revision ID. Two different imported long line IDs could therefore produce duplicate revision IDs in one run. A subsequent retry used only the ID set and could silently treat another line's output as already present. A valid 63-character job suffix could also make the combined revision ID exceed the native 63-character suffix limit.

Root reproduced five failures through the actual generated-image recognition pipeline before correction. No optimizer or fitting was used. The correction preserves exact existing short-ID tokens. New long/overflow identities use the complete run/line pair, serialized with unambiguous boundaries and SHA-256 encoded as a full 256-bit base64url token that fits the native limit. Existing unambiguous legacy long-line L0 identities are reused on retry. Conflicting scope/layer, duplicate target history or input identities receive a typed refusal before persistence; no history is silently rewritten. Global project revision occupancy is checked, rather than only the selected surface's IDs.

The same five tests then passed. Three additional controls cover complete long-run identity, unchanged L1 source history, occupied hashed IDs and duplicate input line identity. An expanded run initially exposed the pre-existing unused `ToDictionary` throwing an untyped duplicate-key exception before the crop-disposal block. Input identity validation now precedes model/image work and that unused dictionary is removed; the failed receipt is retained.

Evidence: `.artifacts/overnight-2026-11-05/recognition-identity-before/` (5 failures), `recognition-identity-after/` (5 passes), and the expanded receipts/logs alongside them. The final expanded group passes15 cases (8 identity and7 existing preprocessing), and the current central no-fitting gate passes1935 with18 intentional skips and zero failures. Tests use a fresh generated PNG and a tiny untrained inference model with explicit disposal, no collection data, target labels, provider or Greek decisions. A cryptographic identity is not a substitute for occupancy checks: a conflicting generated token is still refused. Previously corrupt duplicate histories require repair and are not automatically migrated.

Independent read-only review found no blocking issue and verified the two frozen source hashes: [review record](recognition-revision-identity-independent-review-2026-11-05.md). The corrected source is included in the next isolated worker baseline; no old published worker is substituted.
