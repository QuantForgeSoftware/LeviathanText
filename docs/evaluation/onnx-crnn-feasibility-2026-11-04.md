# C# CRNN ONNX feasibility

November 4, 2026. **Defer product export and retain the native TorchSharp adapter.** The existing C# CRNN is expressible with standard ONNX operators. This review found no supported exporter for the pinned TorchSharp checkpoint, and no ONNX graph or runtime parity has been demonstrated. A separately authorized synthetic-only spike can test a narrow C# graph emitter for this architecture. An independently licensed ONNX inference adapter has a separate intake and parity gate.

## Export and inference are separate

LeviathanText pins TorchSharp 0.107.0 with macOS arm64 LibTorch CPU 2.10.0. The [trainer](../../src/LeviathanText.Training/CtcTrainer.cs) writes named model state using `save`, and the [loader](../../src/LeviathanText.Training/RecognitionModelLoader.cs) reconstructs the architecture before loading those bytes. TorchSharp documents its own tensor-state format. Its ONNX export request is closed as not planned. The 0.107.0 release's `torch.export` support loads already compiled `.pt2` packages from AOTInductor. That upstream path uses Python to compile the package. The repository search found ONNX file classification in migration inventory and no ONNX execution or export dependency. The installed TorchSharp .NET 8 assembly has SHA-256 `4cdbefe569482662109119685a31312c556ce24e67b6daf75eb16cc62264809c`. [TorchSharp state format](https://github.com/dotnet/TorchSharp/wiki/Sharing-Model-Data-between-PyTorch-and-TorchSharp) · [Export issue](https://github.com/dotnet/TorchSharp/issues/1281) · [Release notes](https://github.com/dotnet/TorchSharp/blob/main/RELEASENOTES.md) · [AOTInductor change](https://github.com/dotnet/TorchSharp/pull/1499).

ONNX Runtime's C# `InferenceSession` can execute an existing graph. For a C#-authored model, the plausible path is an architecture-specific emitter using the official ONNX protobuf schema and the validated state of the reconstructed CRNN. Treat each required parameter name, dtype, shape and gate transformation as a checked mapping. A documented Python exporter or an ONNX inference binding supplies a different part of the workflow. [ONNX Runtime C# API](https://onnxruntime.ai/docs/api/csharp/api/Microsoft.ML.OnnxRuntime.InferenceSession.html) · [ONNX IR specification](https://onnx.ai/onnx/repo-docs/IR.html) · [PyTorch ONNX exporter](https://docs.pytorch.org/docs/stable/onnx_export.html).

## First synthetic graph contract

| Boundary | Requirement |
| --- | --- |
| Shape and preparation | Float32 row-major input `[N,1,H,W]` with dynamic batch and width, fixed package height and one channel. Bind the exact typed crop/resize/polarity profile and its expected geometry. Reuse C# preparation and match each line's right-padding background. The current crop preprocessor has a minimum width of eight pixels. A graph contract must reject out-of-range sizes explicitly and record the tested width range. |
| Convolution and sequence | Mirror both same-padding Conv/ReLU stages and the package's two MaxPool strides. Preserve the `C × pooled-height` feature order when reshaping and transposing to `[T,N,F]`, with `T = floor(W / widthDownsampleFactor)`. Verify dynamic shape execution at nonmultiple widths and with mixed-width batches. |
| LSTM and head | The native model uses one forward LSTM with sequence-first layout. Map PyTorch `IFGO` gate rows to ONNX `IOFC` using block order `[0,3,1,2]` for both weight matrices and both bias vectors. Preserve separate input and recurrent bias halves, zero initial state, and the direction axis before squeezing it. Apply the linear head and class-axis LogSoftmax in evaluation mode. |
| Output and CTC | Return float32 `[T,N,C]` log probabilities. Keep ordered labels, blank index zero, actual per-line CTC lengths, greedy or prefix-beam decoding, and Unicode scalar confidence spans in C#. The existing output decoder receives a TorchSharp tensor. A portable runtime should share a runtime-neutral decoding core, preserving argmax tie and beam/alignment behavior. Forced alignment requires a separate compatibility test. |

The graph can initially target ONNX IR 8 and opset 14, subject to session load and per-operator validation on the selected CPU runtime. Pin both versions. Use a synthetic parameter fixture with different values in each gate and bias block to detect a transpose or gate permutation. The [CRNN implementation](../../src/LeviathanText.Recognition/CrnnModel.cs), [batcher](../../src/LeviathanText.Recognition/LineBatcher.cs), [preprocessor](../../src/LeviathanText.Recognition/LinePreprocessor.cs) and [CTC decoder](../../src/LeviathanText.Recognition/CtcOutputDecoder.cs) define the native comparison. [ONNX LSTM](https://onnx.ai/onnx/operators/onnx__LSTM.html#lstm-14) · [PyTorch LSTM parameter layout](https://docs.pytorch.org/docs/stable/generated/torch.nn.modules.rnn.LSTM.html).

## Evidence needed to proceed

1. **Synthetic export.** Freeze the architecture revision and parameter hashes for an invented C# fixture. Generate a self-contained standard-operator graph from that state. Verify tensor names, shapes, ordered byte hashes and every initializer transformation. Test all supported width factors and representative fixed heights. Keep out-of-range dimensions, unknown shapes, custom operators and external tensor paths out of this first graph. [ONNX external data](https://onnx.ai/onnx/repo-docs/ExternalData).
2. **Paired execution.** Feed both runtimes identical prepared float bytes with the same batch shape and padding. Cover widths 8, 9, 15, 16, 17, 31, 32, 33 and a bounded long line, plus mixed-width batches and both background values. Record exact output shape and input-length agreement. Require all finite log probabilities within a numeric tolerance frozen before execution, for example absolute error at most `1e-4 + 1e-5 × |native|`. Require exact greedy and beam CTC indices, strings and scalar span coordinates, with an independently frozen confidence tolerance. Include repeated labels, blank-separated repeats, empty decodes and combining marks. Preserve and explain every failed or near-tied case.
3. **Package and loader.** Create a distinct versioned package/backend contract. Pin graph and source checkpoint SHA-256, graph schema/opset, emitter revision, parameter mapping, class count and label order/hash, preprocessing profile and geometry, author/rights, test receipts and supported runtime/provider versions. Apply the existing package trust and size boundaries and enforce explicit graph/tensor/width/batch limits before session creation. Older native loaders must reject the new package version, and current native packages must reload through the existing route. Verify disposal on load, inference and failure. ONNX data models can still consume substantial resources. [Native manifest](../../src/LeviathanText.Training/TrainingRunManifest.cs) · [ONNX Runtime model validation](https://onnxruntime.ai/docs/#model-validation).
4. **Platform proof.** Use a pinned ONNX Runtime CPU package on actual `osx-arm64`, `linux-x64` and `win-x64` hosts before claiming those targets. Version 1.31.0 is a concrete candidate to verify against the selected runtime assets and current advisories when the spike is authorized. Run the same graph and fixture receipts on each OS, record clean published-host startup and native library resolution, then measure cold load, warm inference and sustained resource use. Keep CPU proof separate from any accelerator provider. Confirm the inference-only host's dependency closure independently of the training host. [ONNX Runtime 1.31.0 release](https://github.com/microsoft/onnxruntime/releases/tag/v1.31.0) · [ONNX Runtime C# package guidance](https://onnxruntime.ai/docs/get-started/with-csharp) · [Current project target evidence](../release/packaging.md).

This review closes the paper feasibility decision. Its evidence covers source and documentation inspection. Execution, package installation, graph creation and weight conversion were outside the review.
