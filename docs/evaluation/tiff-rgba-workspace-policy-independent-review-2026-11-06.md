# Independent TIFF workspace-policy source review

Reviewed the source-only proposal in `.artifacts/experiments/tiff-rgba-workspace-policy-v1`, frozen manifest SHA-256 `175ee171693b7f48f2edf2eeade65af1b077def655240f87a3bdc0bba3273420`, patch `9fab3d77cef0dc73fbf1863682ff1fd744df15a6b008551da2d678c970cc3706`. No build, test, decode, large allocation, model or corpus operation ran. Frozen v16/v17 remain untouched.

No high-confidence blocker was found in the proposed guard and propagation code. Positive int dimensions are multiplied in checked unsigned 64-bit arithmetic; their maximum possible product times 4 still fits ulong. Once byte count is at most512 MiB, conversion to an int element count is safe. The generic full-page and source-block guards precede their int[] allocation. JPEG segment checks precede ordinary output allocation and the native compatibility segment bitmap. The dedicated budget exception is retained through the shown fallback catch boundaries and translated into the existing RejectedArchive contract with invariant requested/limit bytes and a specific reason.

Sentinel tests cover the fixed 11585²/11586² and12000×11184/11185 boundaries without allocating those workspaces. The exact512 MiB scalar case is explicitly outside the public image-axis contract, not claimed as newly admitted imagery. A small six-element actual array checks unchanged zero initialization. Helper test sources are not before-proof on an assembly that lacks the helper, and have not been compiled or executed here.

This is an intentional new refusal for some valid within-dimension/encoded-limit images. Root must explicitly approve that compatibility tradeoff before a fresh versioned candidate. The cap applies to each specified extra owned RGBA workspace, excluding the returned bitmap, precise buffers, encoded/staging arrays, vendor/native state, concurrency and total RSS. Generic full Decode can refuse page scratch even where small-source-segment Band or snapshot traversal succeeds; a smaller returned output budget does not remove full fallback scratch. Native TIFF dispatch and oldJPEG admission remain separate.

Proceeding to a versioned candidate and safe generated proof is reasonable after policy approval and quiet release. Public-route exact reason/ownership proof still needs a bounded candidate-only integration seam or external allocation guard; do not run an unguarded huge baseline raster merely to manufacture failure. Preserve admitted small fixture pixels/decisions, metadata/source bytes, all original strict negatives and independently registered resource results. This review does not establish allocation/RSS acceptance, uniform OOM handling, exact A-assembly coverage, fork security maintenance or dependency migration.
