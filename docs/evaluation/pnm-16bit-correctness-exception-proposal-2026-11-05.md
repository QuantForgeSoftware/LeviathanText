# Registered16-bit PNM correctness exception proposal

No candidate pixels have been observed. This proposal is separate from the already approved10 P5/P6 first-binary-whitespace/hash cases. It does not change TIFF, TGA, QOI, JPEG or other lossless thresholds.

The immutable157-fixture manifest and actual frozen baseline outputs establish12 named cases: P2/P3/P5/P6 with maxval256,1000 and65535, each13×5. Exact complete samples, maxval, encoded SHA256, baseline RGBA, proposed RGBA, pixel SHA256 and every differing pixel are in `.artifacts/experiments/sec01-independent-v1/pnm-correctness-oracles.json`. The oracle script verifies the actual source bytes against its independent generated sample sequence before recording expectations. It does not decode with the candidate or choose a tolerance from candidate results.

The primary [PGM](https://netpbm.sourceforge.net/doc/pgm.html) and [PPM](https://netpbm.sourceforge.net/doc/ppm.html) specifications define a maxval from1 through65535 and two-byte binary samples, most-significant byte first, when maxval exceeds255. ASCII P2/P3 carry their numeric sample values directly. Raster sample scaling into the application's8-bit bitmap needs an explicit rounding policy: this proposal chooses **nearest integer, half upward**, `floor((sample*255 + floor(maxval/2))/maxval)`, independent perRGB channel, grayscale copied toRGB, alpha255. It performs no gamma/color-profile transform. Quantization alone is a declared normalization choice, not evidence of malicious input or a decoder vulnerability.

The old binary observations show large semantic differences: small big-endian16-bit samples at max65535 emerge as their low byte's8-bit value; max256/1000 samples can instead saturate at255. ASCII max256/1000 samples7/14 emerge as0 even though normalization should remain near7/14 or2/4. Exact old/new records distinguish these defects from1-level quantization choices. A case that already matches the proposed normalization remains an exact control.

Requested scope: approve only these12 source-hashed cases and future tests implementing this same explicit16-bit PNM sample rule. Compare them against the independent fixed oracle, including scaled/band derivatives from the corrected raster. Preserve every baseline output and refusal. Keep all other accepted lossless fixtures exact, all source hashes/raw dimensions exact, and the previously registered TIFF-JPEG-only tolerance unchanged. Reject invalid sample values/maxval rather than silently clamp them. P4-first-hash and P7/PAM baseline refusals are capability observations, not required backwards behavior or an implicit exception.

Root approved this exact12-case proposal before candidate evaluation. The10 first-byte cases remain a separate approved exception. `pnm-exception-approval-freeze.json` pins the complete source/raster/derived oracle identities. No production adoption is claimed by this approval.
