# JOB-01 bounded advisory job streams

The application now bounds process-local job-event history and each live SSE queue, while preserving SQLite as the authoritative job resource. Root implemented this against the [fixed contract](../tasks/bounded-job-events-2026-11-05.md). Integration remains pending the current central no-fitting gate; actual browser resynchronization is a separate planned proof.

The defaults retain at most 128 streams, 8192 events and 2 Mi UTF-16 kind/payload characters globally, with bounded event size, subscribers and nested delivery. Each SSE consumer retains at most 256 queued event references/65536 characters and one coalesced wake signal. Pins prevent recycling a stream while it is publishing, replaying or subscribed. An O(1) LRU and zero-pin slot recycling replace the first candidate's costly oldest-stream scan. Nested callbacks still drain in publication order; overflow and oversized payloads become explicit gaps, with bounded callback-failure collection.

The SSE boundary distinguishes a complete retained window from old, evicted, restarted/future or missing history. It clears browser Last-Event-ID with an empty SSE ID, then supplies a freshly authorized SQLite snapshot instead of presenting partial history as complete. Exact current credentials, enabled account/role, membership and current bootstrap configuration are observed before disclosure. Cancellation is checked at entry and between yielded items. Live delivery revisits SQLite/auth within 64 examined entries; terminal state closes the stream. Capacity admission cannot prevent an already durable job operation merely because an advisory cache slot is unavailable.

The JobsPanel bounds displayed events and job rows, rejects old stream/watch/credential callbacks and fetches a current authenticated job snapshot on resynchronization. It does not trust a URL carried by an event. A capacity marker closes automatic reconnect while still permitting the snapshot. One authoritative read lane prevents a late Pending snapshot from replacing a newer terminal list row, and prevents an older list from replacing a newer selected snapshot. A watched job outside the latest 100 rows is fetched explicitly. No credential strings are retained as history.

## Evidence and costs

Root's final focused backend group passes 70 cases in `.artifacts/overnight-2026-11-05/job01/job-focused-v3.trx`; 17 cases exercise actual HTTP, including empty-ID/restart and credential/bootstrap/account revocation. The client focused group passes 12 cases in `job01-client-focused-2.log`. Initial unbounded history/idle-stream regressions failed before implementation. The independent reviewer reproduced four more failures (uncached zero-cursor history and three cancellation boundaries); the same tests pass after correction. The delayed Pending client race has an independent fail-before receipt. See [independent review](bounded-job-events-independent-review-2026-11-05.md).

The [matched resource experiment](job-event-retention-resource-2026-11-05.md) verifies every generated returned/callback payload and retained replay. At 100,000 publications, bounded heap plateaus near 4.59 MiB for 32 subscribers and 0.25 MiB for 1000-ID churn, compared with roughly 57.5–57.9 MiB for the unbounded reference. Event/character counts remain within the registered limits at every checkpoint. These are managed generated-workload results, not a universal API/native RSS guarantee.

There is a remaining measured cost: final v3 publication takes about 9–11% longer with subscribers and 2.1–2.3 times as long in no-subscriber churn (roughly 0.2 microsecond additional work per publication in those short visits). The first bounded implementation was substantially slower; all versions' negative receipts remain. No best-version timing was selected across experiments. The completed [durable SQLite comparison](durable-job-event-comparison-2026-11-05.md) verifies full authoritative-record parity in eight fresh processes. Its subscriber median is3.6% lower and churn2.2% higher, with roughly threefold within-variant churn variation. It cannot establish unchanged application throughput or erase the publication-only slowdown.

## Limits

Character counts are neither byte nor RSS caps. A returned replay can hold the bounded retained window; serialized authoritative SQLite snapshots have a separate lifetime and are not covered by the live-queue character budget. External callbacks can retain payloads, block or cross-publish; pre-existing cross-stream callback deadlocks remain possible for arbitrary user callbacks. Production SSE callbacks only enqueue locally. Cooperative process-local caching is not durable transition audit storage. The runtime's inconsistent raw GetTotalMemory counter is reported without rescaling and is not treated as verified live bytes. No training, real provider or manuscript accuracy claim follows from these engineering checks.
