# TIFF snapshot traversal proposal

Status: source-only proposal, not implemented or approved for production. It follows frozen isolated v14 and addresses the measured archive-validation regression; it does not reopen the owned PNG-parser proposal. No build, fixture evaluation or resource run was launched while preparing this document.

## Problem and unchanged boundaries

R's224-process v13 resource comparison found the6MP deflate-tiled archive case growing from old TargetSize1's32.5ms/.103MiB managed allocation/81.6MiB peak to71.0ms/28.18MiB/202.7MiB. The current TIFF snapshot validator calls full `SafeTiffDecoder.Decode`, constructing a page raster and destination bitmap. Root has withheld ProjectBundle migration and ImageSharp removal.

The proposal retains the exact supplied byte snapshot, caller's25MiB archive cap, current first-IFD metadata/segment/count/dimension budgets, all existing admitted variants, v14's explicit gray-alpha deferral and bounded per-instance diagnostics. It never reopens a source path, follows later IFDs, changes orientation/source bytes or imposes a smaller segment cap. Success means first-frame decoder traversal/decodability; known recoverable truncated JPEGs remain compatibility observations, not proof of complete entropy or encoded-format validity.

## Proposed isolated v15 implementation

Own only copied candidate Imaging files: `SafeTiffDecoder.cs`, `TiffSampleDecoder.cs`, `TiffJpegDecoder.cs`, `ImageValidation.cs`, and any small internal traversal result record. Vendor source/dependency graph remain frozen. Main runtime and ProjectBundle are untouched.

1. Add `SafeTiffDecoder.ValidateFirstFrame(byte[], Header)` using a read-only MemoryStream over the supplied bytes, the current preflight and first-directory dimension agreement, gray-alpha guard and per-instance diagnostics. It selects the same JPEG/precise-sample/generic RGBA branch as Decode; any decoder false/error/incomplete read remains a typed refusal. A warning alone is not silently promoted to an error.
2. Extract precise-sample traversal into one shared block walker with a nullable destination sink. Validation traverses every first-frame source row/tile/plane, performs the existing sample/palette checks and conversion calculations, but allocates no full-page destination. Decode/Band retain their existing output/rounding behavior. Do not duplicate a weaker header-only path or skip later strips because an earlier row decoded.
3. Extract generic RGBA strip/tile walking from the proven Band path. Validation invokes each admitted block's actual `ReadRGBAStrip`/`ReadRGBATile`, checks every return/error, reuses one bounded scratch array and discards the result. Retain the equivalent UINTMAX RowsPerStrip normalization and first-IFD/raw-orientation behavior. A single strip/tile can cover the whole image; this is block-bounded traversal, not universal constant-memory ROI validation.
4. Extract JPEG7 reconstruction/preflight from the existing branch: tables, raw SOI/EOI, SOF dimensions/components, encoded staging and raw codec dimensions are checked identically before allocation. Prefer native scanline traversal over every segment where supported. If native scanlines are unsupported, the existing per-segment GetPixels raster is the explicit compatibility branch, subject to unchanged preflight/budgets; it is not an invented full-page fallback. A one-segment TIFF can consequently require an image-sized segment raster. Record this honestly in the validation result rather than claiming no full raster. Root should confirm this explicit branch before implementation.
5. Return the existing immutable validation dimensions/format plus an accurately named mode such as `tiff-first-frame-decodability-blocks`. Preserve `AllocatedFullRasterDestination` conservatively: false only when no destination/scratch equivalent to a full-page decoded raster was allocated; a whole-frame generic/JPEG segment must not report false merely because it is called a block. Optionally add nonpositional read-only workspace metadata if this meaning cannot be expressed accurately with the current flag; do not change existing call signatures casually.

Largest-source-block scratch, encoded snapshot/staging, vendor codec state and native scratch remain real memory costs. This change targets removal of the extra assembled page destination, not a hard total-RSS or native-time guarantee. No decoder success authenticates source pixels or repairs malformed source bytes.

## Registration required before implementation/evaluation

Freeze v14 source/binary and the proposed diff scope first. R owns independently generated fixtures/oracles and should register these cases before observing v15 outputs:

- Existing complete TIFF functional sets, including BigTIFF II/MM, all8 orientations, first-IFD multipage, palette/u16/planar/associated samples and every existing strip/tile compression route. Canonical associated16 source-equivalence policy is already root-approved; preserve the original21 strict differences, not a generic tolerance.
- All current archive functional controls and8 gray-alpha deferrals. Accepted/rejected decisions, typed failure details and unchanged input hashes must match the v14 policy. Known recoverable JPEGs remain explicitly accepted controls; they are never counted as malformed-refusal successes.
- First/middle/last strip and tile corruption, planar missing data, palette lookup edge, malformed nested JPEG dimensions/components, tables/offset/count/cycle failures, and valid first-IFD followed by broken later directories. Register which failures the existing decoder actually detects before asserting tighter acceptance.
- Snapshot scope may be a nonexistent path; validation must use only supplied bytes. Verify input hashes before/after every process and no created files/native writes.
- Exact metadata/dimensions and bounded diagnostic counts/logging remain unchanged. Long comments/numeric and metadata-cache controls remain separate evidence rather than being silently retimed in this task.

Register the resource schedule, inputs, binaries, fixed order, warmups, operations, watchdog/output caps and comparison metrics before running. Reuse the exact measured6MP deflate-tile regression input and at least a smaller control. Add one safely sized whole-image strip, one whole-image tile, a planar16 block, and JPEG7 tiled/one-strip controls to expose unavoidable largest-block workspace. Freeze source and candidate binaries before R runs the comparisons. Do not allocate a144MP attack image merely to demonstrate the admitted worst case.

Acceptance requires exact functional policy and source closure, no watchdog/log-limit failure, explicit whole-segment allocation disclosure, and resource evidence that the targeted extra full-page destination is removed without an unacceptable CPU/RSS regression. A single timing pair or an allocation-only improvement is insufficient to claim universal performance. Reverse BAAB or further workloads need their own approved registration; the previous168+56 primary visits do not imply unrun followups.

Root must review the proposal and R's acceptance before any ProjectBundle/dependency migration. The65k-line fork's maintenance identity/owner, source-to-built-DLL provenance, exact notices, source-component inventory and independent security monitoring remain production gates even if this resource issue is solved.

## Isolated implementation progress

Root approved the source-only v15 implementation, including the explicit per-segment JPEG compatibility branch. Fresh `candidate-v15` changes only the four proposed existing Imaging files; v14 remains unchanged. Precise-sample validation shares the full walk and computes the same sample/palette reads while discarding its output sink. Generic validation shares all strip/tile reads and skips only the final destination copy. Eligible JPEG7 segments attempt all native scanlines, otherwise use the existing preflighted per-segment GetPixels branch. Whole-frame-sized decoded scratch sets the allocation flag conservatively.

### Independent static flag review and v16

Before any v15 candidate output was assessed, R identified that the precise CONTIG path's one-row destination was not its complete workspace: the vendor scanline reader can retain an entire raw strip. Palette/planar source blocks can also span the complete frame while using less than four bytes per pixel. The initial flag based only on explicit row/buffer bytes was therefore too strong.

Fresh isolated `candidate-v16` preserves v15 and changes only reporting: any whole-frame TIFF source strip/tile sets the conservative allocation flag by geometry, including CONTIG scanline/vendor strip state and JPEG whole-image segments even when native scanline traversal succeeds. Existing full-frame-sized explicit scratch checks remain. The flag is deliberately conservative, not an allocation profiler or guarantee about remaining native state. Pixel interpretation, accepted formats and budgets are unchanged. `candidate-v16-before-source-edit.json` and `candidate-v16-before-build.json` retain the source-only registration. No v16 compilation or candidate evaluation has yet run; the coordinated CPU hold still applies.
