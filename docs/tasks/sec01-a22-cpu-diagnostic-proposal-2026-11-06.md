Both candidate visits show a repeatable phase transition: the first three measured calls are about50–51ms, then the last approaches35ms. Baseline visits transition earlier from about55ms through47–49ms to38–40ms. Allocation also changes between those phases. Final GC snapshots show48 collections in every generation for each baseline process, versus candidate5 gen0/1 gen1/0 gen2. These end snapshots cannot assign a particular GC to a call. Process CPU includes background work; no stacks/JIT events were captured. The original helper inherited most environment variables, so actual CLR tuning cannot now be reconstructed completely.

A tiered/background-compilation or codec-state hypothesis is supported by the call-order shape, but not proved. .NET documents fast initial compilation followed by background optimization and an isolated `System.Runtime.TieredCompilation` switch. That makes a controlled diagnostic meaningful, not a justification to change global production settings or select late favorable samples. ## Concrete source costs

A16's generic ReadRGBATile creates an RGBA reader and a new RGB byte buffer per tile; A21 reuses one raw RGB buffer and skips final RGBA conversion. With96 tiles, raw RGB buffers plus the differing reusable scratch sizes predict18939904 fewer bytes, versus observed18979544. This strongly explains the allocation reduction already achieved by A21; another generic buffer pool would not explain the wall regression.

A second concrete common cost is `DeflateCodec.ZIPPreDecode` calling `ZStream.inflateInit` for every tile/strip. That allocates a new Inflate/InfBlocks state, including a32KiB window and Huffman tables. It plausibly accounts for much remaining managed allocation, but both arms invoke the shared decoder: it is not a demonstrated differential CPU cause. Tiled decode ultimately reaches the same ReadEncodedTile/ZIPDecode work; A16 additionally performs RGBA setup/conversion. There is no well-supported TiffSampleDecoder hot-loop edit to make yet.

Do not blindly replace inflateInit with inflateReset. Fresh arrays contain zeros; reused history/table bytes could change malformed or recoverable-stream behavior. Reset also needs equivalent initial flags, counters, error/adler and dictionary state. Any future reuse is a separately versioned vendor-fork change, with explicit maintenance/security scope, not an unreviewed two-line A22 shortcut.
