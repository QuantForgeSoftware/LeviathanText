# Native rescue for ambiguous bundle identity

Root approved this source-only correction during the long quiet window; no export/test/build/HTTP/model operation has run. Preserve `.artifacts/experiments/bundle-native-rescue-v1/before/ProjectBundle.cs.txt` for coherent before proof.

The previous include-images branch groups captures by ID and keeps the first. Distinct same-ID captures can therefore map two surfaces to one embedded image without validating the second capture's checksum. Duplicate surface IDs also allow duplicate ZIP paths and first-match convenience exports. Native project.json remains intact, so the defect is derived/raster misassociation rather than deletion of native/source bytes.

For duplicate surface IDs or duplicate capture IDs anywhere in their respective project domains, select full native-rescue mode before any convenience exporter or image-payload read. Emit exactly project.json, integrity.json, exports-omitted.json and manifest.json. Native bytes are exactly NativeJson.Save of the supplied project; do not deduplicate/rewrite identities. The manifest retains format/project/surfaces/files/requested-image fields and adds exportMode=native-rescue plus exact reasons/counts and zero included images. All convenience exports are omitted, including project edition, training/CSV/review, per-surface formats and PDFs. Existing source-alias destination guards and staged atomic ZIP publication remain; only image payload reads are skipped, not necessary output/source safety metadata checks.

Valid unique-identity projects retain the existing normal manifest/export path. No ImageSharp or SEC replacement change is included. No ZIP importer exists in current source; this diagnostic/rescue ZIP is not a backup-manifest SQLite restore and makes no automatic restoration claim.

The new five-case Application regression source includes four surface/capture ambiguity × images-requested cases and a normal bundle control. Before the rescue assertion, generated evidence includes source/embedded image hashes, shared image references and duplicate entry names so fail-before receipts describe the actual old mismatch, not just a missing new field. Afterward require exact native preservation, four unique fixed entry names, integrity/reasons, zero embedded images and untouched source payload bytes.
