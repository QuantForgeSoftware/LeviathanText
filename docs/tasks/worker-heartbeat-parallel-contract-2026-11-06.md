# Automatic worker heartbeat: feasibility and parallel implementation contract

Source review only. No implementation, build, test execution, worker dispatch or performance measurement is authorized by this document. It supplements `worker-heartbeat-followup-2026-11-06.md`. Reviewed source hashes are in `.artifacts/experiments/worker-heartbeat-source-review-v1/source-freeze.json`.

## Feasibility and current behavior

A SQLite schema migration is unnecessary. `LeaseInfo.ClaimId` already exists as an optional JSON property; each `TryClaim` generates a new server GUID, and finalization compares both worker and claim. Reuse this field rather than adding a second nonce. Public `Heartbeat(jobId)` currently checks only worker identity; it cannot safely be the automatic callback because an older callback can touch a replacement claim owned by the same host. Renew must require the captured `(jobId, workerId, claimId)` and Running status. Missing/empty legacy claim identities must refuse renewal; newly claimed legacy pending jobs receive a fresh nonce.

`RunNext` synchronously executes a handler with no automatic heartbeat. Existing tests call Heartbeat manually and therefore do not demonstrate renewal while a blocked handler runs. Polling considers Pending only; expired Running jobs are intentionally excluded. Explicit recovery via TryClaim permits expired Running, but its caller must first establish that the old publisher has stopped. Automatic heartbeat must not relax that rule: expiry, renewal failure, process suspension and clock jumps are not evidence that a publisher stopped.

The adapter is nested `Program.LocalStoreJobStore`, backed by the same LocalStore used by handlers. It has no concurrent-use contract. LocalStore exposes `OpenPeer`, not OpenSession: it opens a separate connection without migration/version repair and shares the same-process write lock. Open the peer before handler dispatch and confine it to the renewal task. Independent processes still rely on SQLite plus exact JSON conditional UPDATE, not the shared lock.

Generic `UpdateJob` reads JSON, invokes a pure transition and retries compare-and-swap until it succeeds or the record disappears. That unbounded retry loop and synchronous SQLite busy handling make it unsuitable for a promised bounded timer shutdown. Add a narrow renewal operation that makes at most one conditional write attempt against the current exact JSON, with bounded SQLite command/busy waits, returning an explicit outcome. A competing cancellation/heartbeat/replacement can reject an individual tick; no unconditional SaveJob is permitted. Distinguish ownership lost, transient contention and persistence failure in bounded diagnostics. Do not swallow task faults.

## Compatibility boundaries

No new field means current persisted jobs need no rewrite. A legacy Running lease with null ClaimId remains readable but cannot acquire automatic renewal retroactively; an explicit safe recovery creates a nonce. ContractJson does not retain unknown JSON fields in extension data. Historical binaries that do not know ClaimId may drop it when rewriting a record; mixed-version workers cannot be advertised as nonce-safe simply because JSON deserialization tolerates unknown properties. Drain old worker binaries before enabling the stronger automatic mode, or keep the feature disabled; document the supported minimum worker version. Existing API cancellation and finalization CAS must remain authoritative.

Keep worker default shutdown semantics: Program drains the current handler rather than interrupting publication. Stop and join renewal before terminal/retry publication, then dispose its independently owned connection. An outstanding SQLite call must finish within a documented command bound; cancellation is not permission to dispose a connection underneath a running command. If that cannot be guaranteed with the chosen provider seam, leave rollout blocked rather than detach background work. A lost claim suppresses stale finalization as today; it does not automatically repeat a potentially committed handler side effect. Renewal failure must not itself consume a retry or manufacture a receipt. Noncooperative/native handler execution cannot be forcibly made safe by a managed cancellation token.

## Instance A: engine and durable renewal

Own only WorkerHost.cs, IJobStore.cs, Program.cs adapter/wiring, a new small worker renewal-lifetime module, and narrowly scoped LocalStore renewal/peer configuration hunks. Coordinate LocalStore hunks with root before edits. Contracts/JobsAndFrames.cs should remain unchanged unless a separately reviewed necessity appears. Root owns shared plans, default policy, integration and package publication.

Before editing, publish these exact interfaces for instance B: an immutable captured attempt identity; an owned renewal-session factory independent from the dispatch store; a one-attempt renewal result discriminating renewed/lost/contended/fault; clock/tick abstraction usable without sleeping; and a RunNext opt-in lifetime configuration. Avoid adding accidental concurrent-use requirements to ordinary in-memory IJobStore implementations. Use a per-attempt factory, not a global Timer or a static shared connection. Validate positive lease/interval/timeout options before opening stores.

Acceptance: automatic renewal actually starts around handler execution and continues during a blocked synchronous handler; each tick uses the captured nonce; no resurrection of Cancelled/terminal/replaced attempts; finalization joins renewal first; no background task or peer survives any exit path. Preserve completed-attempt counts, retry-safe Pending backoff, priority ordering, permission checkpoints and outputs. Keep disabled defaults compatible until root explicitly chooses rollout. Structured diagnostics contain job/worker/claim identity and bounded failure categories, not source paths/secrets or unlimited exception payloads.

Handoff: freeze source/package hashes, explain thread/connection ownership, provide exact positive/negative outcomes and cleanup receipts, and call out any bounded-wait limitation. Never claim lease renewal supplies distributed exactly-once publication.

## Instance B: independent generated verification

Own new test files only, with no edits to A's production paths or existing test fixtures. Proposed files: Worker.Tests/AutomaticLeaseRenewalTests.cs and AutomaticLeaseRenewalProcessTests.cs, plus Infrastructure.Tests/LeaseRenewalSessionTests.cs. Inspect actual project directories before creating files. Own isolated generated seed/handler/process harness and registration artifacts. Obtain A's interface contract before writing mocks; adversarial tests must exercise the production lifetime, not a manually called Heartbeat seam.

Capture a genuine before failure first: run current RunNext with an event-gated generated handler, advance the controlled clock beyond the lease while it remains blocked, and observe unchanged LastHeartbeat/expired ExpiresAt from an independent store. Do not call Heartbeat in the test. New engine must renew before releasing that same handler. A separate small real-clock, two-process SQLite proof verifies actual independently owned connections; register fixed durations/intervals/deadlines before execution, use no models, and retain observed lease timestamps and claim identities. Do not reclaim a live expired publisher merely to demonstrate expiry.

Required regressions: nonce A cannot renew replacement nonce B even with the same worker; wrong worker/job/null claim refuses; terminal/API-cancelled rows remain unchanged; cancellation/replacement between renewal read and CAS cannot resurrect; a slow tick is joined before finalization and its late write cannot renew the next attempt; startup/handler exception/normal success/cooperative cancellation/shutdown all close session/task exactly once. Inject contention/storage failures and prove diagnostics observed without retrying a committed output. Exercise OpenPeer ownership and a second independent-process connection, preserving exact final outputs/attempt IDs. Use thread-safe test stores only where explicitly needed; don't concurrently access the existing dictionary fixture.

Use generated tiny payloads and a deliberately blocked handler, never training/recognition/native models. Register wall/CPU/RSS/log/process cleanup caps and exact binary/source/input hashes before subprocess execution. No resource or throughput acceptance claim follows from functional timing. A separately authorized overhead comparison is required later.
