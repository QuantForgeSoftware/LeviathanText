# JOB-01 durable-write cost comparison

Root prepared this source-only follow-up during the SEC-01 quiet window. Do not build or execute until the independent imaging evaluator releases that window. It supplements the [managed bus comparison](../evaluation/job-event-retention-resource-2026-11-05.md); it cannot erase its measured publication slowdown.

Freeze `.artifacts/experiments/job01-durable-v1/source-freeze.json`: the same current Contracts/Core/Formats/Infrastructure source, actual JobEnqueuer source and one harness, with the prior unbounded bus versus final bounded v3 as the sole variant. Build both with the same SDK, configuration, framework and RID; hash complete binaries and copied native SQLite dependencies before launch. No API host, image/model, fitting, corpus, labels or provider. Every process uses a fresh owned SQLite database. No production source changes are part of this comparison.

Two fixed workloads use deterministic generated job IDs, owner, creation time, inputs and priority. The first updates 32 running jobs in 320 rounds, with one synchronous validating subscriber per job (10,240 durable writes/events). The second updates 1,000 jobs in ten rounds without subscribers (10,000 writes/events). All but the final round use actual `RecordProgress`; the final round uses actual `Complete`. Seed writes and schema initialization are outside timing. Expected full JSON is constructed before each operation; every returned record, each callback payload/sequence/kind/job identity, and all final SQLite records are checked exactly. No field normalization or dropped IDs/clocks is needed. Transcript and final-state SHA-256 must match across variants and visits.

Run sequential fresh-process ABBA for each workload, eight processes total, without other CPU workloads. Seal execution registration before the first process. Operational aborts: 180 seconds wall, 120 seconds CPU, 512 MiB sampled RSS, 64 KiB stdout/stderr per process; sample owned-process RSS/CPU every 250 ms. Stop on parity failure, timeout, process ownership ambiguity or closure drift. Preserve all failures; do not rerun selectively. Never signal a process not launched by this registration.

Report each visit and medians for the timed full loop and durable method calls separately, total allocated bytes, post-forced-GC heap/committed/fragmented bytes and sampled RSS. GC and final SQLite validation are outside timing; callback validation is inside method timing in both variants. Raw GetTotalMemory remains a qualified runtime counter, not verified live bytes. This small local-store workload has no API/network/concurrent worker and cannot establish general throughput, statistical significance or universal memory acceptance. State the remaining bus-only slowdown even if durable-write timing makes its relative cost small.
