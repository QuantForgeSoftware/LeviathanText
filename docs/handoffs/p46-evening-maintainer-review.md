## Demonstrated corrections

**Trainer ownership.** `CtcTrainer` now implements idempotent `IDisposable` for its owned Adam optimizer. The caller retains its model. Mutating/native/checkpoint operations reject use after disposal before filesystem or state changes. The CLI disposes trainer before model through separate `using` declarations. On the installed CPU runtime, disposal promptly releases 20 optimizer tensor aliases without forced GC while retaining caller model/tensor usability. This is relative lifetime evidence, not a unique-allocation count, sustained RSS benchmark, or speed claim.

**Training alphabet.** The CLI previously included development graphemes when defining output labels. New training derives labels only from training data, then rejects development OOVs before model construction, with source IDs, occurrence counts, original graphemes, and scalar codes. The synthetic defect reproduction contains two development lines with three OOV occurrences; the candidate returns exit 1 and creates no package. The compatible control preserves the original training label order and excludes locked-only labels. No scholarly text, normalization, split policy, or pixel transformation changes.

**Failed loading.** A digest-valid but unreadable weight file previously left the newly created model owned by nobody on failure. The candidate uses a bounded construction/load scope, disposes its owned model on failure, and preserves the direct library exception type/message. Successful loads transfer ownership as before and remain usable for inference, parameter access, and byte-identical saving. The final fixture validates the lifetime oracle with raw-tensor-to-Parameter handle transfer; it uses thread-local disposal statistics rather than misleading residual `Tensor.TotalCount` growth. Earlier exploratory loader results using that invalid oracle are superseded and retained in the original experiment folder.

## Compatibility, review boundaries, and remaining checks

There is no change to public model/loader signatures, architecture, forward arithmetic, weight format, labels of existing packages, preprocessing profiles, or stored model semantics. Existing trainer callers remain compatible and opt into deterministic disposal. The new `LabeledLine.SourceId` is optional, retains the existing two-argument constructor, and is omitted from JSON when null; its round trip and `with` propagation are tested. Because it is a record property, equality can distinguish different SourceId values; reviewers should assess any consumers that rely on record equality. The identity is `XML filename#imported sanitized line-ID suffix`, not a new global or lossless external-ID contract.

Concurrent/GPU use, failed model construction before ownership exists, OOM behavior, allocator caching, sustained RSS, and general performance remain outside these narrow proofs. No performance tolerance has been loosened and no speed improvement is claimed. Missing broad manuscript/papyrus/inscription acceptance evidence remains missing.
